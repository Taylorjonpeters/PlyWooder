# PlyWooder documentation

Full feature and test reference. For a quick start, see the [README](../README.md).

## What it does

- **Reads the parts.** Each solid's largest flat face sets its thickness direction. The tool projects the solid onto that face to get the true through-cut outline: notches, slots and through holes. Faces that sit between the two skins become pockets, with their depth. Parts that are not flat stock (such as turned legs) start unticked.
- **Reads DXF drawings too.** Supports lines, arcs, circles, polylines (including bulge arcs), ellipses, splines and block inserts. Open pieces are joined end to end into closed outlines. A loop inside another loop is a hole, and a loop inside a hole is a part of its own. Text inside an outline names the part. Outlines on `POCKET_*` layers become pockets. A drawn sheet border is skipped. Units come from the file's `$INSUNITS`, or you can set them. You set the thickness, since a drawing is flat. Re-importing a PlyWooder export brings the parts back with their names and skips its helper layers.
- **Manual Cut or CNC.** On first visit you choose how you're cutting (you can skip the question; it starts on Manual Cut); a switch at the top of the sidebar changes it later. The sidebar, steps, packing and exports follow:
  - *Manual Cut* (table saw or track saw): strips-and-rows packing on a standard sheet with your blade width, a numbered through-cut order, and DXF/SVG of each sheet. A *Stock needed* line lists the sheets to buy.
  - *CNC router*: true-shape nesting. Pick the machine, the GORDIX table and the sheet in step 2 (Layout); the sheet is an X × Y size: type the sheet you have, press *Use table max* for the most the GORDIX table reaches, or press *Suggest size* for the smallest piece of a stock sheet that fits the parts on as few sheets as possible, plus a margin (50 mm by default) with the parts centred. A size bigger than the table reaches gets a warning. The outline bit sets how far apart parts sit. Machine, table and sheet are set once, in step 2, and the G-code step shows them read-only, so the layout and the G-code always agree.
- **Three steps.** The tabs run in order and the sidebar follows the step: **1 Import** (open a file, tick parts, set thickness and units; shows the model as designed, in 3D), **2 Layout** (machine, table, sheet size, margins, rotation, packing; shows the packed sheets), **3 G-code** (CNC only: bits, operations, fit, cutting, preview), **4 Visualize** (the parts-to-sheets animation). Each step has a *Next* button. A newly opened file is not packed until you press *Pack* on the Layout step, so you can set the machine, sheet and spacing first; after that, a settings change shows *Repack*. Manual Cut has Import, Layout and Visualize (steps 1 to 3).
- **X / Y axes.** Sheets use machine coordinates: X is the length, running left to right, and Y is the width, running bottom to top, with the origin at the lower left. The sheet fields read *X length* and *Y width*. Each sheet drawing has red X and green Y arrows at its origin corner.
- **Groups by thickness.** Each stock thickness gets its own set of sheets. When the parts don't fit on one sheet, the layout continues onto more.
- **Two packing modes.**
  - *Manual cut*: three-stage guillotine layout. Crosscut strips, rip rows, then crosscut parts. Every cut runs edge to edge, so a table saw or track saw works.
  - *CNC cut*: true-shape nesting on a fine grid. Each part goes where it grows the used area least, with a search over part order. Small parts can nest inside holes and notches. Uses the least plywood.
- **Margins.** Sheet edge margin, bit or blade width, and an extra gap for human error. Parts are kept at least *bit + extra gap* apart. On the CNC flow, *Center parts on the sheet* moves each sheet's parts, as one block, to the middle of the sheet (the edge margin still holds).
- **Shared cuts (common-line cutting).** On by default. Neighbouring parts sit exactly one bit apart, so one pass cuts both edges. After the grid pass, the efficient nester slides every part left and down until it butts against a neighbour. It then keeps the candidate layout with the fewest plunges and the least cutting. Off: parts get the extra error gap and are cut separately.
- **Through cuts.** In either mode, PlyWooder finds the straight lines that run edge to edge across the sheet, or across a piece already cut free, without touching a part. It splits the sheet recursively and numbers each cut in order. The sheet view draws them and lists them as "Through-cut order". It also reports which parts can only be freed by a CNC or jigsaw. They export on the `SAW_CUTS` layer.
- **Cut plan.** Each sheet's toolpaths are merged into one network, with shared edges cut once. The network is split into passes that run straight through junctions. Lines that stop within the edge margin get a lead-in to the sheet edge, so the cut starts outside the material. Passes are ordered so each starts at the sheet edge or on an earlier cut where possible. A *plunge* is a pass that has to start mid-sheet. Each sheet shows plunges, passes, cut length and shared length. "Show cut paths" draws the network, with shared runs highlighted.
- **Display.** Toggle between actual cuts and convex hulls. Hulls also pack as hulls, so no part goes into another part's notch. Lengths show in mm, cm or inches: a switch at the right of the tab bar, also in the first-visit chooser.
- **Rotation.** Any 90° turn, grain-locked (0°/180° only), or 45° and 15° steps.
- **Export.** DXF (R12, mm or inches; cm exports as mm), per sheet or all sheets, plus SVG. DXF layers: `CUT_OUTSIDE`, `CUT_INSIDE`, `POCKET_<depth>`, `CUT_PATHS`, `SAW_CUTS`, `LABELS`, `SHEET`. `CUT_PATHS` holds the merged tool-centre passes in cutting order. Profile it *on the line* with the same bit, so shared edges are cut once. Round holes are written as true circles. DWG is a closed Autodesk format. Every CAM package reads DXF, and any CAD program can re-save it as DWG.
- **G-code (step 3).** A CAM workspace for each sheet of the layout. It writes `.gcode` for the [GORDIX](https://gordix.muherz.com/en/) in the dialect [GORDIX Studio](https://pfsin555.github.io/Gordix-studio/) writes ([source](https://github.com/pfsin555/Gordix-studio)), or for a generic GRBL machine.
  - **Operations, in order:** laser part labels (optional), pockets, holes and slots, then outlines. Holes are cut while the part around them is still attached. Outlines use the merged cut network, so shared edges are cut once.
  - **Bits:** a job bit list, with a bit picked for each operation. A *preset* bit comes from the bit library and is locked; *Customize* makes it an editable *custom* bit, and its save icon stores it in the library and swaps the job's bit for the saved, locked one. The library is a modal with folders, and stores manufacturer, part number, diameter, flutes, lengths, tip angle, RPM, feeds and depth per pass, like Fusion. It starts with SED0602(60L), IAP0901 ZRN and ICSMC090-0609 (60° V bit), and can import and export JSON. It is saved in the browser with your settings. A bit's RPM goes into the file's `M3`/`M5`. The GORDIX has no tool changer, so consecutive operations on one bit share a file and each bit change starts a new file. Each file's header says which bit to load and to re-zero Z.
  - **Fit:** measured stock thickness for each thickness in the layout, which sets the through and tab depths. A fit allowance makes slots, holes and pockets wider and tabs and outlines narrower. Dogbone corners notch inside corners so square tabs seat.
  - **Cutting:** depth steps per bit, cut past bottom, safe height, pocket stepover, and optional ramped entry. Ramping is off by default, as GORDIX Studio plunges straight down and its editor can't read the step-down of a ramped file. Holding tabs go on outlines, and optionally on holes.
  - **Preview:** the toolpaths per operation, tabs, travel moves, the GORDIX work area and the origin. A strip of sheet thumbnails, grouped by stock thickness, picks the sheet (arrow keys work too). A play/scrub bar moves the bit through the whole job with its file, operation, Z and elapsed time. There's a run-time estimate for each file and for the job. A *Stock* badge shows the piece each sheet needs.
  - **GORDIX dialect:** `G21 G90 G0 G1` and `;` comments only, with X, Y and Z always written to three decimals as Studio does. F is modal and the GORDIX applies it to `G0`, so, like Studio, every file opens with `G0 X0 Y0 F2000` before any Z move. It lifts with `G0 Z<safe>` and lowers with `G1 Z<depth> F300`. XY rapids also carry `F2000`. Router files never send `M3`/`M5`, which switch the GORDIX laser; label files use `M03 S255` / `M05` like Studio's. X0 Y0 is the sheet centre, Z0 the top of the material, and files end at X0 Y0.
  - **GRBL dialect:** `M3 S<rpm>` / `M5`, `M4` for the laser, a lower-left origin and `M30`.
  - **Tables and work area:** the GORDIX reaches less than the table it stands on. Pick one of its five tables, or load your own `table.cfg` exported from GORDIX Studio's table setup page. The tables are saved with your settings. Load `table.cfg` and *Studio defaults* are in step 2. With the GORDIX machine the sheet follows the table's work area, using Studio's formula: Studio's default 2560 × 1460 mm table gives 2280 × 1038 mm, and a 4 × 8 ft table gives 2158 × 830 mm. In the GORDIX table setup, S and N are the horizontal (X) edges and W and E the vertical (Y) ones, so the first value is X. On a table whose X side (S) is the short one, the G-code turns the sheet 90° so its long side runs along machine Y, and the file header says so. Cuts outside the work area, or deeper than the 30 mm Z travel, are flagged.
  - **Dry run:** three downloads for the sheet on screen, so a test run never needs a setting changed and back. *Air cut G-code* writes its cutting files raised by *Air cut height* (25 mm by default): the whole job runs in the air and nothing touches the material. Laser label files are left out, since the laser would still mark. The normal downloads are never raised.
  - **Bounds (registration):** *Bounds G-code* under Dry run writes a file that lifts to safe height, moves the bit centre to the stock sheet's lower-left corner on the machine (lowest X and Y, even when the sheet is turned 90°), and stops there with the spindle and laser off. Zero the machine as for the real files, run it, and line the stock's corner up under the bit. The stock sheet is the sheet size on the Layout step: the table's work area, or the custom or suggested size.
  - **Pen stock edge:** *Draw stock edge with pen* under Dry run writes a pen plotter file that draws a [ bracket where the stock sheet goes: its whole left edge on the machine (lowest X), plus the first 100 mm of its top and bottom edges, so the stock can be pushed up against it. Put a pen in the machine instead of the bit, zero X and Y as for the real files and Z with the pen tip touching the surface. The pen comes down to *Pen depth below Z0* (1 mm by default, so it presses on the material; a spring-loaded holder takes up the extra) at 300 mm/min, draws at 1000 mm/min, then lifts to safe height. The spindle and laser stay off.
  - **Stock support:** the GORDIX drives on the surface under it. When the sheet (the stock) is smaller than the table's work area, PlyWooder applies Studio's work-area formula to the stock itself to find how far from its centre the machine can go before it runs off an edge. Any download whose moves go past that (travel included, and always for *Bounds G-code* and *Draw stock edge with pen*, which go to the stock's edge) first shows *Tool path crosses bounds of stock*. *Add scrap* downloads anyway, for when you surround the stock with scrap of the same thickness; *Change safe area* goes back to the Layout step's sheet edge margin, and the dialog says how far in from the edges the parts need to stay. The Layout step's Margins section carries the same reminder for the GORDIX.
- **Tooltips.** Many ⓘ tips include a small drawing.
- **Loading indicator.** Packing, Suggest size, and reading STEP, DXF and table files show the animated logo (a plain spinner with reduced motion). It appears only if the work takes more than a moment.
- **3D / Animate (Visualize step).** The model as designed, then every part flies to its spot on the packed sheets, using the layout's sheet size, gap and margins. It plays once the first time you open the step after a file loads. Use play/pause and scrub. The Import step shows only the model: no animation and no sheets. Unticked parts show faded.

## Tests

```bash
npm test -- path/to/model.step
npm run test:dxf
npm run test:cam
npm run test:labels
npm run test:through
```

`npm test` runs the STEP → parts → nesting → DXF pipeline in Node. `npm run test:dxf` re-imports that DXF, and also imports a hand-written drawing with arcs, bulges, blocks, inch units and a sheet border. `npm run test:labels` checks that part names never sit over a hole. `npm run test:through` checks that each through cut names the piece it is made in. Both build their own parts, so they need no sample file. `npm run test:cam` checks the toolpaths and G-code on hand-made parts and the samples, one behaviour per check. The checks cover cut order, one file per bit change, depths and measured thickness, ramping, tabs, dogbones reaching slot and notch corners, fit allowance, both dialects, laser labels, air cut, and the GORDIX work area. It writes sample files to `scripts/out/`. The DXF test also checks that no two parts come closer than the requested gap and that every part stays on the sheet.
